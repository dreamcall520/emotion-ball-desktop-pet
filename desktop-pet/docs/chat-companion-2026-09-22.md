## 初次开发阶段记录

## 对话规则

- 启动球球零连接；打开聊天面板只检查登录，不创建 Codex 对话。
- 首次发送创建专用对话，保存编号后再发送消息。后续消息、面板关闭重开、应用重启都使用这个编号。
- 仅主动“新聊天”清除当前指向，下次发送才创建新对话。不会自动重发，不会在恢复失败时自动另建。
- 创建结果不确定时保留标记、提示处理；本机存储失败时停止后续发送。账号变化隐藏原记录。
- 回复完成并保存后，才允许执行固定的球球动作；中断、失败、格式错误或重复通知不能重复执行。

## 接入与界面

独立聊天 App Server 连接与原额度/任务只读连接分离；界面为贴近球球的 360×480 原生窗口，支持流式回复、停止、新聊天、浅深色、中文输入法与草稿恢复。聊天面板打开时暂时让出气泡和额度卡位置；隐藏球球会一起隐藏面板，锁屏会停止回复，退出只关闭本应用拥有的连接。

使用本机 Codex 的 ChatGPT 登录和可用额度，不提取或复制登录凭据。每轮消息强制空执行环境，关闭命令、文件、插件、MCP、搜索等能力。Codex 强制加载默认全局 `AGENTS.md` 或 `AGENTS.override.md`，保留这些用户使用偏好，只接受这两个精确来源，拒绝其他项目指令来源。

## 协议核验发现

1. 首次 `account/read` 可以先触发 `account/updated`。旧响应被作废后最多补一次只读确认；不会因此新建或发送消息。
2. `thread/start` 后未发送任何消息的空对话，关闭所属进程后可能无法 `resume`。用户首次发送过程中不会主动关闭连接；遇到不可恢复情况仍提示错误。本次早期权限探针留下的空编号已单独保留证据，没有把它报告成有效持久对话。
3. 当前版本 `thread/resume` 会恢复默认本机环境，且协议没有环境设置接口；真正 `turn/start` 可以在模型执行前指定 `environments: []`。恢复阶段仅允许空环境，或唯一指向专用聊天目录的本机环境，禁止恢复仍在执行的任务。每轮真正发送时必须清空环境。
4. Codex 同一对话只允许一个写连接。正常关闭改为关闭 stdin、读取剩余输出并等待子进程退出，再允许恢复；异常占用返回专门提示。没有删除锁文件或修改 Codex 数据库。本次曾遇到占用冲突，具体持锁者未能追溯确认，不能把退出竞争宣称为唯一根因。

## 复核入口

常规检查：`node --test desktop-pet/tests/*.test.js`。

面板原生检查：`node desktop-pet/scripts/smoke-chat.js`，脚本会启动隔离的 Electron，仅使用模拟数据。

主流程原生检查：指定独立 `--user-data-dir`，设置 `PET_SMOKE_TEST=1 PET_SMOKE_CHAT_ONLY=1` 后用 Electron 启动项目；会输出 `PET_CHAT_INTEGRATION_OK`，不调用真实模型。

真实聊天检查：`PET_CHAT_LIVE=1 PET_CHAT_LIVE_SEND=1 PET_CHAT_LIVE_DIR=/absolute/isolated/path node desktop-pet/scripts/verify-live-chat.js`。此命令消耗 Codex 额度，目录必须专供验收；仅账户检查可省略 `PET_CHAT_LIVE_SEND`。脚本不会自动清除失败会话。只有明确设置 `PET_CHAT_LIVE_NEW=1` 才备份旧验收记录并开始新聊。
