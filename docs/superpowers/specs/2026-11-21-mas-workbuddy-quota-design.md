# 商店版 WorkBuddy 额度接入

日期：2026-11-21。基线：`release/app-store@f6dbd04`。本次分支：`feature/mas-workbuddy-quota-20261121`。

## 目标与范围

将官网版已有的 WorkBuddy 余额、基础／奖励／购买积分、刷新与到期信息、消耗统计接入商店版。沿用现有额度卡和详情布局，保留账户切换保护、精确金额校验、错误分类和真实零余额语义。用户随后明确追加官网同款「进行中／待查看」任务入口，读取当前账号本机任务元数据并提供合法会话跳转。商店版聊天来源仍只有 Codex；WorkBuddy 聊天、插件、网站登录、CLI 与趣味游戏不开放。

## 授权与读取

参考现有商店 Codex 的两步授权，用户先明确选择已安装的 `WorkBuddy.app`，再选择 `~/Library/Application Support/CodeBuddyExtension/Data/Public/auth`。两项书签独立于旧任务目录授权保存，完整验证后原子提交；取消或失败不覆盖已有可用记录。后台启动只恢复已有授权，不弹选择器。

额度查询在两项授权作用域存续期间，使用用户安装的 WorkBuddy 组件读取所选账号目录，执行限定的 `quota` 或 `usage` 操作。任务元数据需要第三项独立的 `.workbuddy` 目录授权，存入 `store-workbuddy-task-grants`，不复用账号目录授权；仅在 `tasksEnabled` 明确允许时执行 `tasks`／`task-open`，按当前账号过滤标题、缓存状态、未读标记和更新时间，不读取聊天正文，不改原软件未读状态。查看与全部已查看只更新球球自己的提醒；跳转由主进程复核当前账号、条目及固定 `workbuddy://chat/` 链接后打开。

书签和凭据不传给页面，不写入日志，不发送模型消息。取消、关闭、撤销与账户变化后丢弃迟到结果，进程确认退出后释放作用域。缓存历史不作为实时进行中数量；原客户端未同步实时状态时仍明确显示未知，沿用官网当前语义。

## 商店渠道边界

保留 `mas-first` 发布配置，不随包分发第三方运行时。保留 WorkBuddy 额度窗口、受限适配器、查询与投影依赖、任务元数据 reader／controller／renderer、独立任务授权模块和图标；裁剪旧网站／CLI／聊天／插件／游戏模块和厂商源码。任务 renderer 及原 HTML 引用原样进入暂存目录，与官网同款页面资源保持一致，由明确能力控制启用。继续保留协议参考的 MIT 归属声明。官网构建不执行该裁剪。

设置中心提供独立 WorkBuddy 连接引导及积分卡显隐。额度卡仍参与现有收纳、排序和固定展示；`quotaOnly` 持续关闭聊天与游戏，任务和结果入口由单独的 `tasksEnabled` 能力控制。解除连接停止查询并撤销该连接授权。

## 验证与完成边界

自动检查覆盖应用／账号及独立任务目录授权成功／取消／失败／过期／恢复／撤销，作用域与进程生命周期，操作白名单、当前账号任务过滤和合法链接，状态与凭据投影，商店菜单和真实 `prepareStaging` 再裁剪后的资源与模块完整性；回归现有 Codex 和官网 WorkBuddy 行为。
