# 商店版 WorkBuddy 额度接入

日期：2026-11-21。基线：`release/app-store@f6dbd04`。本次分支：`feature/mas-workbuddy-quota-20261121`。

## 目标与范围

将官网版已有的 WorkBuddy 余额、基础／奖励／购买积分、刷新与到期信息、消耗统计接入商店版。沿用现有额度卡和详情布局，保留账户切换保护、精确金额校验、错误分类和真实零余额语义。商店版聊天来源仍只有 Codex；WorkBuddy 聊天、任务、插件、网站登录、CLI 与趣味游戏均不开放。

## 授权与读取

参考现有商店 Codex 的两步授权，用户先明确选择已安装的 `WorkBuddy.app`，再选择 `~/Library/Application Support/CodeBuddyExtension/Data/Public/auth`。两项书签独立于旧任务目录授权保存，完整验证后原子提交；取消或失败不覆盖已有可用记录。后台启动只恢复已有授权，不弹选择器。

每次查询在两项授权作用域存续期间，使用用户安装的 WorkBuddy 组件读取所选账号目录，执行限定的 `quota` 或 `usage` 操作。书签和凭据不传给页面，不写入日志，不发送模型消息。取消、关闭、撤销与账户变化后丢弃迟到结果，进程确认退出后释放作用域。

## 商店渠道边界

保留 `mas-first` 发布配置，不随包分发第三方运行时。只保留 WorkBuddy 额度窗口、受限适配器、查询与投影依赖及图标；裁剪旧网站／CLI／聊天／任务／游戏模块和厂商源码，额度详情的任务脚本在暂存阶段移除。继续保留协议参考的 MIT 归属声明。官网构建不执行该裁剪。

设置中心提供独立 WorkBuddy 连接引导及积分卡显隐。额度卡仍参与现有收纳、排序和固定展示，任务、结果与游戏入口通过明确的 `quotaOnly` 能力关闭。解除连接停止查询并撤销该连接授权。

## 验证与完成边界

自动检查覆盖两步授权成功／取消／失败／过期／恢复／撤销，作用域与进程生命周期，仅额度操作的执行边界，状态与凭据投影，商店菜单和裁剪后依赖完整性；回归现有 Codex 和官网 WorkBuddy 行为。

源码和模拟测试通过只表示本地接入完成。真实 MAS 沙盒下的系统授权、WorkBuddy 组件启动与真实额度一致性需要独立原生验收；打包、安装、TestFlight、提审和商店发布分别记录，不能由源码测试推断。
