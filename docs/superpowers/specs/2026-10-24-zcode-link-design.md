# ZCode 联动：与 Codex 平级的完整功能方案

日期：2026-10-24。状态：已按用户要求修订范围，未实施。当前源码核验基线为 main `03b7aac`（v0.4.06），不再沿用前轮 main `3e1c90d` 或旧工作树作为实时基线。

## 用户明确要求

设置可独立开启 ZCode 联动；开启后可设置是否展示额度卡；额度卡展开可看明细、趋势、进行中任务；支持通过 ZCode 与球球聊天；UI 和交互跟现有 Codex 一致。此前仅额度小卡的建议已被本要求替代，不将任务、趋势或聊天删出范围。

## 用户看到的功能

| 位置 | 行为 |
| --- | --- |
| 设置 | 新增与 Codex 平级的「ZCode 联动」总开关，沿用现有设置分组、控件和连接状态样式 |
| 联动子设置 | 开启后可单独控制「显示额度卡」；隐藏卡片不等于关闭任务连接或聊天能力；关闭总联动则停止 ZCode 的后台连接和请求 |
| 额度卡 | 同样的紧凑/展开、点击入口、明细窗口、主题、字号、贴边和收起规则；清晰标识来源 ZCode |
| 额度明细 | 按套餐、活动、模型、周期显示真实余额、总额、更新时间、刷新/到期时间；不把多桶伪装成两条 Codex 周期 |
| 趋势 | 沿用现有图表与切换交互，选择对应额度桶/模型；按 ZCode 实际日周期、五小时、周周期或一次性活动记录 |
| 进行中任务 | 入口、任务列表和状态呈现与现有一致，展示 ZCode 真实执行状态；点击定位对应任务，跳转能力须验证后启用 |
| 与球球聊天 | 沿用同一聊天面板、消息流、历史、新聊天、停止、模型选择、错误反馈及动作表现；增加 Codex / ZCode 来源选择 |

只启用一家时，聊天直接用该来源；双开时保留当前来源，不自动把现有 Codex 对话改成 ZCode。切换来源时恢复各自的会话和模型选择，不把另一家的历史自动发送过去。回复进行中沿用现有忙碌约束，等待结束或主动停止后再切换。

双开时各自保留额度卡和开关，使用现有视觉规范及避让规则。不能因新增 ZCode 直接改变 Codex 的位置、已保存偏好或数据。空间不足如何布局，应在实际双卡/三卡边缘场景验证，保持展开入口可达。

## 复用与隔离

复用已有 UI 样式、窗口、图表、列表和聊天呈现，不另画一套。给共享展示增加最少来源信息（来源名、桶标识、周期名称等），默认值保留 Codex 原行为；原调用方和测试必须继续通过。

ZCode 自己负责账号、认证、余额映射、任务状态、聊天协议、历史和错误恢复。Codex 原取数、任务、历史、提醒、聊天记录保持原语义；不重构整个应用，也不将 ZCode 伪装成 Codex 线程。

源码已确认的必要适配：

- `desktop-pet/quota-label-renderer.js` 与 preload 对两条额度有数量限制，存在 CODEX 固定标题；ZCode 多桶必须通过自己的展示模型和受校验字段进入共享 UI。
- `desktop-pet/codex-details-preload.js:18` 只接受 300/10080 分钟，`codex-quota-history.js:20` 只接受 `codex:` 标识。保留 Codex 数据格式，ZCode 用独立记录文件及桶/周期标识，不能把每日/一次性活动强写成五小时或一周。
- `desktop-pet/lib/chat-companion.js` 含 Codex 错误文案、账号/线程状态；`chat-models.js` 有 OpenAI 模型族自动选择逻辑。ZCode 需自己的协议和模型选择适配，复用消息/动作呈现，不套用 OpenAI 模型选择。
- `desktop-pet/lib/codex-chat-rpc.js` 的聊天连接已经独立于额度/任务连接，并禁用文件、终端等工具能力。ZCode 聊天应保持相同产品边界，只接受文本及球球现有动作白名单；不因换后端获得额外操作权限。

## 取数与协议证据

**已实测：** 当前账号 ZCode 自有活动/体验四桶，官方 balance GET 返回 HTTP 200 / code 0，已与原生 UI 对照，见 [脱敏响应](本机直连-脱敏.json)。本轮没有发起模型请求。

**本机源码已确认、尚未真实收发：** `/Applications/ZCode.app/Contents/Resources/glm/zcode.cjs` 内建官方 `app-server --stdio` 会话协议，包含会话创建、列表、读取、订阅、发送、取消和流式事件。无需为了聊天直接依赖第三方 ACP 桥。应按当前 CLI 实际 schema 适配，不照搬 Codex app-server 请求。

[官方 CLI 文档入口](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/usage/README.md)；[命令参考](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/usage/02-cli-reference.md)；[权限说明](https://github.com/zai-org/ZCode/blob/main/apps/zcode-cli/docs/usage/05-permissions.md)。官方也说明源码与不同构建能力可能不同，最终以本机二进制握手和运行验证为准。

**任务跨进程状态尚待验证：** 新起 app-server 的存量 session/list 不足以证明 ZCode 桌面另一个进程里的任务正在执行。本机源码会为数据库会话缺省 idle，再叠加本进程活跃会话；桌面 host 另维护 tasks-index、活跃任务投影和事件订阅。因此「能列历史会话」不能算「进行中任务已接通」。必须只读适配桌面真实状态源，并验证执行中、等待确认、完成、失败和取消，不通过改写其任务库实现监控。

**聊天认证尚待真实验证：** 额度接口成功不等于模型请求成功。Start Plan 模型请求还有账户运行时认证/签名等交互，需要按官方协议处理。遇到验证码或权限确认时交还用户，不自动绕过，不偷偷切到付费通用 API。实际发送聊天会消耗当前来源对应的额度，启用联动本身不主动发送消息。

## 趋势的业务边界

- 开启后记录真实余额样本，按账号、供应商、套餐实例、模型/余额桶、当前周期分别保存。
- 未有权威历史余额时从首次记录起画，不编造启用前的曲线。样本不足显示「记录中」，断网缺口不画成完整连续消耗。
- 每日刷新开新周期；一次性活动结束标到期；新增赠送、额度恢复与模型消耗不能混算成负消耗。保留原生数据的服务端时间、单位、余额和总量。
- 同样的图表 UI 可展示不同周期，但标题和横轴必须反映真实日/周/活动范围。

## 验证顺序与完成判据

1. 独立协议探针：只读列会话/订阅桌面任务，验证官方 CLI 握手、认证、权限能力、连接退出；不先改现有 Codex。
2. ZCode 独立状态和记录：余额、桶周期、趋势、任务及聊天会话适配均有针对性测试。
3. 复用 UI：总开关/卡片开关、展开、明细/趋势/任务、聊天来源切换；不是用新样式替代原 UI。
4. 真实账号验收：真实任务生命周期、双向流式聊天/停止/重开/恢复、Start Plan 可用性；身份切换后旧请求不能污染新账号。
5. Codex 回归和最终包验证：四种双开组合、原历史/设置/任务/聊天、窗口避让、锁屏隐藏、退出清理、新文件打包白名单。

任务或聊天遇到限制时保留在目标范围中，如实标「待验证/受阻」，不以简化成额度卡宣称完成。当前只是调研与修订方案；未改球球源码、未安装、未消费模型额度。
