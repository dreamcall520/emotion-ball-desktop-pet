# WorkBuddy 第三方应用接入草稿

状态：可审阅草稿，未创建应用、未提交审核、未申请权限、未部署服务。

应用名称：球球桌宠。

用途：用户主动连接自己的 WorkBuddy 后，在球球查看云端任务状态，并主动向本地助理发送消息、读取对应回复。积分展示使用独立网站会话；不把兑换积分接口当成余额查询。

拟申请范围：`user.task.readable`（云端任务列表/详情）、`user.localassistant.readable`（本地助理在线与消息）、`user.localassistant.invokable`（用户主动发消息）。暂不申请创建云端任务、联系信息或积分兑换权限。

接入约束：应用须审核启用并取得相应权限；普通官网登录不能代替 OAuth 授权。官方接口中的云端任务与本地助理在线状态不代表全部桌面任务。向本地助理发消息会触发其执行，应在球球清楚展示目标和等待审批；尚未证明其支持专用“只聊天”隔离会话，不得沿用 Codex 的无工具承诺。

需要落地的外部配置：经过平台认可的应用类型（文档对硬件接入/Buddy 应用的表述不同，需后台实核）；正式 HTTPS 服务域名与回调地址；平台应用审核及所需 scopes。当前未提供这些配置。

服务端换票：随机、一次性并绑定球球会话的 state；校验回调后由服务端请求官方 `/openapi/v2/token`。client_secret 与 refresh_token 留在服务端，不能放入 MAS 包、渲染页面或日志。未选择部署服务与归属前不构造假回调、不提交任意域名。

验收：真 OAuth 回调→范围回读→本人任务状态→一次专用消息→回读实际消息及归属；每一步分别记录。网站登录、HTTP200、接口mock通过均不能替代此链路。
