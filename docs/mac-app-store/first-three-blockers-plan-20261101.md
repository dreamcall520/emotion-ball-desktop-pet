# 0.4.10：前三项卡点处理方案

状态：只读核查后的实现方案，未据此修改产品、切换账号或发送模型消息。

## 1. 账号一致性

以球球实际发送聊天的账号为主。Codex额度改由同一个随包官方组件、同一独立profile查询，不再把原Codex目录账号的额度默认配给球球聊天。固定0.166.0官方协议支持account/rateLimits/read及account/logout，但当前球球RPC白名单尚未放行，需实现与沙盒验证。原软件任务单独标来源，可继续看，不默认为聊天账号任务。

统一身份契约须包含服务、稳定账号ID、个人/团队及workspace范围；API来源还需实际接收服务及密钥的本机不可逆摘要。现Codex聊天hash邮箱、原额度hash account_id不能直接比两个hash；同邮箱也不能证明同workspace。

同工具卡显示额度账号/聊天账号/原任务来源，支持已核实一致、已确认不同、无法核实三种状态。无法核实不阻塞独立可用能力，也不冒充同一计费来源。WorkBuddy目前网站积分、CLI聊天、桌面缓存没有共同可比较的稳定身份，先保持独立来源，只有实际拿到稳定ID后才合并。

增加“更换聊天账号”：停止当前回复并等待退出、只退出球球独立profile、清空内存身份和旧授权同意、新账号官方登录后新建隔离会话，旧记录保留；不得修改原软件登录，不得将旧消息/迟到额度结果串给新账号。Codex有官方logout路径；WorkBuddy需验证官方登出能力，不把disconnect当logout，也不默认删除整份profile来代替退出。

验收：同账号显示真实额度；不同团队/账号不混用；换号期间旧响应丢弃；新账号旧记录不自动发送；原软件登录和配置保持。

## 2. ZCode官方聊天

代码证据：mas-provider-runtime.js prepareChat仅在configured-custom时开启免配置直连；official无外部service时直接返回未完成，localChat直连fallback也固定configured-custom。因此“只要开通套餐即可在球球官方聊天”不成立。

官方配置文档明确Coding Plan专用端点仅限Coding场景，通用资源包/充值余额使用另一端点。不能为球球日常闲聊把Coding套餐转成通用API，也不能因原工具内一次请求成功就宣称用途支持。

处理：官方账号继续提供可读取的套餐额度与原任务，聊天能力单独判断；已有兼容通用自定义模型保持免手填复用、显示独立API计费。官方聊天继续研究厂商公开支持的授权/嵌入或通用服务入口，补齐接收服务身份与发送同意后再实测；尚无支持入口时如实标示此来源不支持普通聊天，而非催开套餐、反复授权或偷偷切到自定义API。完整官方聊天目标仍未完成，不将替代通道算作官方通道已通。

若将来有支持的官方入口，验收需覆盖实际有权限账号、无套餐/到期/限额、个人/团队切换及拒绝自动切费；当前不要求用户先付费。

## 3. WorkBuddy信息完整性

历史任务可复用已授权目录中的元数据读取器；实时任务复用既有Hook事件，两者接回统一详情页，展示来源、时间与核实范围。不能用旧缓存冒充正在运行，Stop与主回复FinalStop不能合成为所有后台任务完成。无新事件的任务显示当前状态未核实。

用量：球球已登录官网的独立Electron Session可作为后续适配入口，先以该Session验证官方页面所用明细接口，复用纯aggregateUsage计算，补当天/近7天趋势和更新时间。旧readWorkBuddyUsage入口会用桌面refreshToken换网站cookie，禁止直接接回MAS；不读取原桌面凭据，也不新增要求用户复制密钥/终端配置。接口返回敏感附加字段不展示/持久化，纯用量投影及实际响应范围需单独核验。会话过期只恢复官网积分登录，不重做CLI聊天/插件授权。

既有企业资格阻塞针对开放平台硬件/Buddy应用申请，不能扩大为“所有WorkBuddy用户必须企业账号”。若完整云端任务/团队终态只能由该开放平台提供，则保留为外部接入待解决，不能伪造完成。

验收：历史与实时同页但来源清楚；重启旧事件不冒充实时；官网账号切换丢弃旧明细；用量失败不影响聊天；统计窗口/延迟可见。

## 顺序

先做Codex同账号额度与三家账号来源说明，再接回WorkBuddy历史/实时详情，随后验证官网Session用量明细；ZCode官方普通聊天保持单独可行性门槛。以上均需新0.4.10真实MAS包回归，不能沿用旧候选通过结论。
