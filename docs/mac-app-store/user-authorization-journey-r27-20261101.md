# R27 商店版用户授权链路审计

2026-11-01。只读审计 `feature/mac-app-store` 当前实现（HEAD `96d934d`）；不代表正在整合的 0.4.10 新树已验收。未发起账号、模型或权限请求，未修改源码/用户设置。本文不是开发者签名、证书、App Store Connect 或送审步骤；这些均由开发方承担，不计入用户操作。

## 结论

可以把球球的入口统一为“选工具 → 启用所选授权”，并复用已有效的授权、登录和同意；**不能承诺首次使用所有功能总共只点一次**。首次官方登录、系统目录许可、插件写入新用途、首次 AI 发送及便签整理的独立用途，有不同对象和影响，需清楚说明后由本人确认。

当前实现保留了聊天、额度、任务和便签智能整理的入口，但能力边界必须明确：

| 工具 | 聊天 | 额度 | 原工具任务 |
|---|---|---|---|
| Codex | 球球随包组件、球球内独立官方登录、球球自身聊天；不等于原工具聊天/同一账号 | 授权 `.codex` 后读原工具账号额度 | 目录内部分任务日志；没有明确运行证据的记录保持未知，不声称原工具全部任务覆盖 |
| ZCode 自定义 | 从已授权配置连接受支持的自定义服务，沿用原 API 计费；不让用户填端口/密钥 | 官方套餐与自定义 API 分开，不能拿官方套餐额度代表 API 余额 | 本机缓存；安装球球任务插件后获取原工具事件，停止事件不证明最终完成 |
| ZCode 官方套餐 | 当前商店 `prepareChat` 未完成直接聊天；开套餐不能据此保证聊天可用，不自动切到自定义 API | 原目录账号的官方套餐查询，空套餐据实显示 | 同上，独立于聊天是否可用 |
| WorkBuddy | 随包官方组件、球球内独立官方登录、专用聊天；不接管原桌面聊天 | 官网积分是可选独立登录，只有网站汇总，不证明与球球聊天账号相同 | 历史缓存需明确选择匿名账户范围；插件提供原工具主回复事件/部分终态，不代表后台整体任务完成 |

## 计数口径

以下数的是**不同确认/操作事件**，不把一次官方登录说成一次鼠标点击。官方页面可能要求账号选择、扫码/验证码、协议等多步，实际点击数由厂商决定，本次没有打开登录页核数。

- **R：球球启动操作**。当前单卡是“启用授权”打开引导，再点“继续”，共 2 次；批量是勾选工具后点“启用所选授权”1 次。全选按钮另 1 次，若逐个勾选另计 1–3 次。
- **C：球球原生用途确认**。如“同意并发送”“同意安装插件”，每个已说明的用途计 1 次。
- **S：系统目录确认**。预定位正确工具目录后点“允许连接/允许安装”，每个工具首次缺有效书签计 1 次；不要求用户输入隐藏路径。
- **L：官方登录流程**。每种独立登录计 1 个流程，具体点击数不定。
- **E：退出原 App**。仅插件实际写入/重新配对且原工具运行时，完成原任务后本人 `⌘Q` 退出计 1 次；不强杀。成功后球球请求自动重新打开，无需另找启动器。
- 业务操作“打开聊天、选择聊天工具/模型、输入、点发送、生成整理”另计，不属于额外权限；下表未计滚动、展开详情等导航动作。

前提：原工具已安装，ZCode 已有受支持的自定义配置，套餐/网络有效，用户选择完成相应能力。未安装、套餐无效、系统书签失效会增加补救操作，不能用固定次数包办。

## 首次安装球球：当前实际路径与成本

### 单卡默认引导

| 场景 | R | C | S | L | E | 说明 |
|---|---:|---:|---:|---:|---:|---|
| Codex：沿当前引导完成聊天+原数据，并首次发消息 | 2 | 1 | 1 | 1 个球球内 Codex 登录 | 0 | C 是首次聊天数据同意。聊天本身不需要目录；**当前引导仍会自动继续请求原数据目录** |
| ZCode 自定义：聊天+原数据+插件，并首次发消息 | 2，另选择自定义来源 1 个动作 | 2 | 1 | 0 | 0–1 | C 分别为插件写用途、首次向所选自定义 origin 发送；原目录书签经明确写用途同意后复用，不重复弹系统目录 |
| ZCode 官方：套餐/原数据+插件 | 2 | 1 | 1 | 0 个球球新登录 | 0–1 | C 为插件用途。原账号须已在 ZCode 登录；当前直接官方聊天不可用，不存在“完成这些就能聊天”的承诺 |
| WorkBuddy：聊天+原缓存+插件，并首次发消息 | 2 | 2 | 1 | 1 个球球内 CodeBuddy/WorkBuddy 登录 | 0–1 | C 分别为插件用途、首次专用聊天数据同意；官网积分登录未包含在内 |
| WorkBuddy：另开官网积分 | 1 个“授权官网积分”入口，另有导航 | 0 个球球 AI 数据确认 | 0 | 新用户另 1 个官网登录 | 0 | 登录成功自动查询，不需人工复制 cookie/密钥；官网登录与聊天登录目前不共用 |
| Codex：首次便签智能整理 | 1 个业务“生成整理”动作，另有打开便签/整理面板 | **另 1** | 0 | 已有球球 Codex 登录时 0 | 0 | 独立 notes 用途，发送当前标题正文；拒绝不建整理线程/模型 turn，不发送其他便签或原聊天 |

ZCode 自定义来源不是默认。需先打开该工具引导选择“已有自定义模型”，再继续；默认官方来源不能自动改成自定义以凑齐三家聊天。普通模型已有可用默认时无需强制再选；原模型失效需用户选择可用模型。

### 批量连接全部工具

全选后点“启用所选授权”，启动控制共 2 次（全选 1 + 启用 1）；之后程序顺序推进，已完成项跳过。**不是将三家权限合成一个系统授权**。

若预先为 ZCode 选择受支持的自定义来源，并完成三家聊天、全部原数据与两家任务插件，首次每家发消息的确认预算为：

- S：3 个工具目录各 1，共 3 次。两家插件复用有效书签，通常不再加 S。
- L：球球内 Codex、球球内 WorkBuddy 各 1，共 2 个流程；若也要 WorkBuddy 官网积分，再加 1 个独立流程。
- C：两家插件写用途 2 + 三家首次聊天数据同意 3，共 5 次；首次便签整理再加 1 次。
- E：0–2 次，取决于 ZCode/WorkBuddy 原 App 是否正在运行。等待本人退出后自动继续，不要求终端。
- 选择 ZCode 来源、打开聊天和明确发送消息是业务动作，不应隐藏或自动替用户执行。

当前批量默认仍选 ZCode 官方；因此未预选自定义时不能直接套用上述“三家聊天成功”预算。暂不可用、取消及等待首次正常任务事件不会强制重复授权；后续可从单卡继续。

## 原工具已安装与球球已有安装，不能混为一谈

- **只有原工具已安装/已登录，但球球第一次安装**：Codex/WorkBuddy 球球专用登录通常仍需首次本人登录，不能复制原 App 凭据以省一步。ZCode 自定义可在目录授权后沿用原配置，不额外索取 key。系统目录授权也仍是给球球的新授权。
- **同一商店版身份/同一用户数据下，球球已有有效授权**：目录、球球独立登录、插件用途和已确认 AI scope 均可复用；重复打开工具卡不应重选目录、重登录或重装插件。
- **官网版/诊断候选迁移到正式商店版**：不同容器、bundle/signing 身份或 profile 下能否继承不是当前通用保证。必须在新安装场景验收，不能把本开发机的既有授权当成新用户零操作证据。
- 已在原工具装好球球插件，但没有球球的相应用途许可：先说明新接收/更新连接信息用途 C1；若原目录已有有效书签，S0，否则 S1。只读许可不是默认具有安装代码/改插件设置的用途许可。
- 只有配对用途，后来构建具备完整插件安装能力：扩展到代码/设置写入需再确认 C1，可复用有效技术书签 S0，不得静默升权。

## 日常重启与正常使用

在同一有效账号/来源/用途下：**新增权限确认 C0、系统目录 S0、官方登录 L0、退出原 App E0**。球球只恢复之前开启的工具，后台恢复不弹新登录、不自动发模型消息。

- Chat scope 同意已保存、账号已核实：每次本人发送不再弹相同原生框；新聊天/换本地会话也不因此重复用途同意。
- 便签 notes scope 与聊天分开；同账号已确认 notes 用途后，整理其他单条便签不重复同意，但每次仍需本人触发整理。
- 插件接收器与已安装插件状态恢复；等待原工具下次正常使用产生事件，不要求为“确认连接”另发测试模型消息，也不把旧事件冒充实时。
- 官网 cookie 有效时积分可恢复，不能规定每天重新扫码；失效才本人重登录。
- 目录失效只补对应 S1；登录失效只补对应 L1；不能连带撤销其他已可用工具或强制重走全套引导。
- 未知账号身份的诊断/旧连接不永久保存 AI 数据同意，会每次询问；这不是普通托管新用户的目标体验，应提示身份未核实，不能偷用旧 provider 级同意消除提示。

## 换模型、来源、账号与撤销

| 用户操作 | 必要确认/重连 | 不应重复的步骤/当前缺口 |
|---|---|---|
| Codex 同账号普通模型切换 | 选择模型；不自动发消息 | 不重做目录/登录/AI 同意 |
| ZCode 同服务 origin、同凭据普通模型切换 | 选择模型；实际来源保持 | 不重复 AI 同意；不因失败静默切官方/API |
| ZCode 换自定义 origin 或 API 身份 | 下一次明确发送前 C1；重连后必要时开始新会话 | 不应因 API 来源变化让用户重选仍有效的目录；旧会话不可跨账号续用 |
| ZCode 官方↔自定义 | 明确选择来源并连接；新 scope 首次发送 C1；当前官方聊天仍有限制 | 不是开套餐就必然能官方聊天；也不能自动回退其他计费来源 |
| 原 Codex/WB App 换账号 | 原数据刷新按真实新账号结果显示 | 不代表球球专用聊天登录也变了；两者归属未核对时保持说明 |
| 球球内 Codex/WB 换聊天账号 | 理应有球球内“更换登录账号”→本人官方登录 L1→新 scope 首次发送 C1 | **当前未找到面向用户的换号/退出独立登录入口**。现有解除授权保留独立 profile，再启用可能恢复旧账号，不能宣称这就是换账号 |
| 只撤销 AI 数据同意 | 每工具 C0 个撤销确认；下一次该工具聊天发送/便签整理重新 C1 | 不退出账号，不重选目录，不停原工具；Codex 按钮当前同时清聊天和 notes 两种 scope，应文案说明 |
| 完整解除该工具再连 | 解除后禁用自动恢复、忘记原数据与插件用途、清 AI 同意；再连需该目录 S1、插件新用途 C1、下一次 AI 发送 C1 | 独立登录文件未清除，仍有效通常 L0；插件源码/原 App 启用记录不会自动卸载。接收停止≠源端过滤脚本已移除；重连可能需更新 receiver，原 App 运行时 E1 |
| 只停任务事件接收再恢复 | 当前恢复会重新准备接收器/连接信息，按原用途有效性确定 C0/1、S0/1；实际写入时可能 E1 | 聊天/额度保持；不要把“停止接收”说成卸载，或要求用户重做聊天数据同意 |

身份/会话/窗口在同意过程中变化、窗口关闭或锁屏：拒绝派发，原文/草稿保留。用户取消显示“消息未发送”，不是连接失败；不自动重发。

## 最小必要修正建议（本审计不改源码）

### 送审前应决定/修正

1. **让“可选”与自动流程一致。** 目前 `buildProviderGuide` 的原数据 `data` 步没有 `optional:true`，两家 `tasks` 安装也属于批量必经项；所以聊天已可用后仍自动请求目录/插件，用户只能取消或暂缓。这是可消除的摩擦。建议引导先选择“聊天 / 原工具额度与任务”，原功能全部保留；仅 ZCode 自定义聊天必需读取模型配置。聊天用户不要被追加原工具权限。
2. **补球球内换号入口或明确暂不可换。** 用官方受支持的退出/重新登录方式，先停止本账号会话，清对应 AI 同意再本人登录；不要让用户找终端、删 profile，也不要靠解除目录授权伪装换号。旧会话保留但不可跨账号发送。
3. **ZCode 来源选择应在排队处理前明确。** 当前默认官方，批量可直接处理官方失败后请求原数据；建议第一次触及 ZCode 前先让用户选官方或已有自定义，不自动更换计费。官方聊天未支持应直接说明，允许继续额度/任务，不重复登录或授权来“修复”。
4. **先定义最短聊天路，再提供完整联动路。** Codex/WB 最短必要链是球球启动 → 官方登录一次 → 本人首次发送同意；不必读原数据、不必退出原 App。ZCode 自定义是选择来源 → 系统允许原配置一次 → 首次发送同意。不减少任何能力，只延后非当前目标所需权限。

### 可合并复用但不能静默扩用途

- 原数据读取和任务插件都由用户明确选中时，可在同一家工具的一次清楚用途说明后复用同一系统目录选择；现代码已做到“已有读书签 + 明确写用途同意 → 不再弹第二个目录”。不要把已读许可当成用户已经同意安装脚本。
- 插件本机过滤/写设置与 AI 内容发第三方不同目的，不应用一个笼统“开启联动”替代。聊天与便签 notes 的数据集合也不同，首次用途同意保持独立。
- 正常恢复/检查已有插件先只读检查；若代码、记录、receiver 都无需更新，应立即报告已连接，不要求退出原 App。当前高级“安装或更新”点击后 runtime 在判断是否需要写之前先等待原 App 退出，有避免空跑的空间。
- “授权所选”应顺序安排各家实际系统/官方确认，记住已完成步骤；不要用新的球球确认页复述同一个已同意 scope。签名/上架/插件审核由开发方处理，不加进用户引导。

## 代码证据与验收边界

- `desktop-pet/store-connections-renderer.js`：`startFlow/pumpFlow`（约142–167行）；单卡启用仅 `openGuide`（约178行），继续才启动；批量对 `needs-authorization` 步骤自动推进，取消/不可用暂缓。`provider-authorization-flow.js` 仅跳过 `optional` 或已尝试项。
- `desktop-pet/lib/provider-connection-guide.js`：`buildProviderGuide/pluginSteps`；官网积分明确 optional，原数据 data 未标 optional；首次事件等待 informational、不反复安装。
- `desktop-pet/lib/mas-enable-flow.js`：`enable` 聊天后只非交互恢复数据；`enableData` 单独交互授权；`restore` 不打开系统选择器/新登录。
- `desktop-pet/lib/mas-provider-runtime.js`：`prepareChat/prepareWorkbuddyChat`、`ensureDirectory`、`ensurePluginAccess/installProviderPlugin/restorePluginInstallations`。目录书签有用途字段；实际安装等待本人退出原工具；受沙盒能力/构建策略限制时不假称已装成功。
- `desktop-pet/lib/mas-directory-access.js`：三家目录预定位、明确读/安装/配对用途、取消保留旧授权。
- `desktop-pet/lib/chat-data-consent.js`：provider+channel+origin+账号指纹+版本/计费生成scope；同意后重核窗口/账号/会话；仅保存version/provider/scope；notes 独立channel；拒绝不发送。
- `desktop-pet/lib/zcode-direct-chat-rpc.js`：所选路由的 origin+凭据指纹用于同意分域，非普通模型名；Coding专用不适用端点拒绝。整个配置的聊天账号键另有更严格变化检查，改配置可能需要新聊天，不等于需要重复目录许可。
- `desktop-pet/main.js`：`registerStoreConnections`、`storeChatSendWithConsent`、`requestStoreNotesConsent`、商店 `createMasEnableFlow` 接入；整体解除授权不删除独立登录profile；当前未发现退出球球专用登录/换号操作。

以上为当前源码路径与必要操作预算，不是对每个新用户/每个厂商登录页的逐点击实测。三家实际账号、最终0.4.10合并树、开发/分发包与新用户空profile场景仍应分别验收；既有机器联调通过不能替代新安装体验。本文没有新增任何授权、写入原工具配置、发送模型消息或提交商店。
